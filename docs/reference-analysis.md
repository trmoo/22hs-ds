### 4-6. 차트를 라이브러리 없이 해결한 방법 — 3계층 (이 레퍼런스의 핵심)

**(a) Canvas 2D 손코딩 5개** — 개념마다 하나씩, 공용 함수 없이 각각 처음부터 작성. 5개가 공유하는 레시피:

```js

var DPR = window.devicePixelRatio || 1;
cv.width = cv.offsetWidth * DPR; cv.height = cv.offsetHeight * DPR;
ctx.setTransform(DPR, 0, 0, DPR, 0, 0);                    // ① 레티나 보정
var padL=40, padR=14, padT=14, padB=28;                     // ② 여백 수동
function px(x){ return padL + x/XMAX*(W-padL-padR); }       //    도메인→픽셀 클로저

ctx.strokeStyle="#334155"; /* L자 축, 격자선은 아예 없음 */    // ③ 축

/* ⑤ 마크: arc(r 3~5) 데이터 #5eead4, 선 #fbbf24 lineWidth 2.5~3.5 */
/* ⑥ 범례·수치·해설은 캔버스가 아니라 DOM 형제 요소(.reg-readout, .sim-log) */

```

**(b) 순수 CSS/DOM "차트"** — 캔버스가 필요 없을 때. `div` 트랙 + 그라데이션 fill의 `width` 트랜지션(`.dd-bar-fill` 1s, `.nz-fill` .8s, 이징 전부 `cubic-bezier(.2,.7,.3,1)`), flexbox 누적 100% 막대(`.ratio-bar`, 비율을 인라인 `flex:80/12/8`로), 절대배치 마커가 있는 1차원 수직선 게이지(`.smp-line`), 통계 타일(`.rep-stat`, `.ar-m`, `.ev-card`).

**⚠️ 말로만 나오고 그려지지 않는 차트**: 히스토그램(6개 파일), 상자그림(2), 원그래프(4), 꺾은선(3), 막대그래프(4)가 본문에 언급되지만 **실제로 그려지는 건 하나도 없습니다.** 2-2차시 `📊 그래프 처방전`은 차트 이름과 **2.4rem 이모지**(🏔️ 분포, 🥧 비율)를 보여 주고, 4-2차시 `🏔️ 분포 보기` 버튼의 출력도 **텍스트 카드**입니다. 히트맵·워드클라우드는 언급조차 없습니다.

### 5-2. 서버 — **Python FastAPI/Starlette + Cloudflare** (헤더로 검증)

| 근거 | 관찰 |
|---|---|
| 404 본문이 `{"detail":"Not Found"}` (JSON, 22바이트) | **Starlette/FastAPI 기본 에러 포맷**. nginx면 HTML 에러 페이지, Express면 `Cannot GET`, Flask면 HTML 404 |

| **HTML은 ETag·Content-Length 없이 `cf-cache-status: DYNAMIC`** | 정적 파일과 다른 경로로 서빙됨 → `추론:` HTML은 디스크에서 읽어 **후처리 후** 반환하는 커스텀 파이썬 라우트 |
| `subjects.py` 언급 | 챗봇 위젯 주석에 `되살릴 때는 subjects.py·랜딩 카드와 함께 …` → 서버가 파이썬 |
| `POST /api/chat` 스트리밍 | `추론:` FastAPI `StreamingResponse`로 LLM 토큰 스트림 중계 |
| `Server: cloudflare`, `cf-ray`(NRT/HKG), `Report-To: cf-nel`, `alt-svc: h3` | Cloudflare 프록시 경유(오리진 헤더는 숨겨짐) + Cloudflare Web Analytics |

**가장 중요한 발견 — 챗봇 스크립트 태그는 서버가 주입합니다.** 직접 검증했습니다:

```
lesson02.html        last-modified: Wed, 17 Jun 2026 16:25:54 GMT
chatbot-widget.js    last-modified: Thu, 30 Jul 2026 11:55:27 GMT, etag: "1785412527"
epoch 1785412527  =  2026-07-30 11:55:27 UTC   ← 정확히 일치
```

6월 17일 이후 수정되지 않은 파일이 **7월 30일 mtime에서 유도된 버전 스탬프**를 담고 있을 수는 없습니다. 따라서 서버가 응답할 때마다 `<script src="/chatbot-widget.js?v={int(mtime)}" defer>`를 끼워 넣는 것이고, **저작자의 원본 파일은 인라인 `<script>`에서 끝납니다**(Cloudflare 비콘도 자동 주입). 이 설계 덕분에 플랫폼을 고쳐도 콘텐츠 26개 파일을 건드릴 필요가 없습니다.

부수 확인: `/chatbot-widget.js`는 StaticFiles가 아닌 **전용 라우트**입니다 — `Content-Type: application/javascript`(charset 없음), 정수 ETag `"1785412527"`, 코퍼스에서 유일한 `must-revalidate`.

### 6-2. 수업에서 짚어야 할 내용상 유의점

버그는 아니지만 교사가 알고 들어가면 좋은 지점입니다. 코드를 직접 읽어 확인했습니다.

1. **k-평균 시뮬레이터가 그 차시의 경고를 스스로 지키지 않습니다.** 3-3차시는 `📏 거리로 유사성 재기 — 주의: 정규화!` 박스에서 나이와 구매액을 반드시 정규화해야 한다고 가르치는데, 정작 `dist()`는 **원단위 유클리드 거리**를 씁니다(`Math.sqrt(dx*dx + dy*dy)`, 311행). 이 데이터에서는 두 범위가 우연히 비슷해 결과가 그럴듯해 보이지만, 학생이 "k-평균은 스케일 조정이 필요 없구나"로 잘못 배울 수 있습니다. **수업에서 명시적으로 짚어 주는 편이 좋습니다.**
2. **향상도(lift) 판정에 공개되지 않은 완충 구간이 있습니다.** 본문 용어 설명은 `1이면 무관`이라고 하지만 코드는 `lift > 1.1`만 양의 연관, **`0.9 ≤ lift ≤ 1.1`은 별도로 `거의 무관`** 으로 분류합니다(337·340행). 10건짜리 거래로 과잉 해석을 막는 합리적 설계지만 학생에게 설명되지 않습니다.
3. **경고 박스의 예시를 도구로 재현할 수 없습니다.** 3-4차시는 `"빵 → 봉투" 신뢰도 90%`를 흔한 상품의 함정 사례로 드는데, **`봉투`는 분석기의 품목 목록에 없습니다**(본문·해설·퀴즈 3곳에만 텍스트로 등장). 학생이 직접 확인해 보려 해도 불가능합니다.
4. **같은 통계를 두 차시가 다르게 구현합니다.** 중앙값이 2-1차시에서는 짝수 개까지 처리하는데 2-4차시는 `sorted[Math.floor(n/2)]`로 홀수 전용입니다(하드코딩 n=7이라 결과는 맞음). 오차 지표도 3-2차시는 RMSE를 `오차 크기(점)`로, 3-5차시는 MAE를 `평균 오차`로 — **서로 다른 지표를 비슷한 한국어 이름으로** 부릅니다.
5. **정규화 위젯의 "이전/이후"가 서로 다른 스케일입니다.** 원본 모드는 전체 최댓값(`GLOBAL_MAX = 30000`)으로, 정규화 모드는 속성별 min-max로 그립니다. 그래서 `데이터` 막대가 정확히 50%인데 설명은 `막대를 거의 다 차지해요`라고 말합니다.
6. **개념 지도가 안 배운 용어를 씁니다.** 2단원 개념 지도의 4차시 노드 라벨에 `교차검증`이 있는데, 2단원 4차시는 일관되게 `여러 방법으로 비교(상호 대조)`라고 하고 교차 검증은 3단원 개념입니다(노드를 클릭하면 나오는 상세 설명은 맞게 적혀 있어, SVG 라벨만 잘못된 것).
7. **4단원 단원평가가 각 차시 확인 문제의 재활용에 가깝습니다.** 11문항이 대체로 1~4차시 확인 문제와 대응되고 표현만 압축됐습니다. 서술형에서만 다루는 삼각 검증·데이터 스토리텔링은 평가에 등장하지 않습니다.
8. **잘린 축의 아이러니** — 2-4차시 `기간 자르기` 차트의 y축이 260에서 시작합니다(0 기준선 없음). 같은 단원 2차시 심화 박스가 `y축을 0이 아닌 데서 시작해 작은 차이를 크게 부풀리기`를 왜곡 기법으로 가르치는데, 이 차트가 그것을 하고 있습니다. 차시의 논지(같은 데이터로 다른 이야기 만들기)에는 부합하지만 의도된 것인지는 소스로 판단할 수 없습니다.
9. **잘 만든 부분도 기록해 둡니다** — 상관 탐험기는 표본 r이 목표 구간에 들 때까지 재추출해 **그림·숫자·설명이 절대 어긋나지 않게** 만들었고, k-평균은 빈 군집 가드와 전용 안내 문구까지 갖춘 정직한 Lloyd 알고리즘이며, 연관 분석은 `맥주→기저귀` 지지도 0.30 / 신뢰도 60% / 향상도 1.50이 심화 박스의 손계산과 정확히 일치합니다. 3-4차시에는 한국어 조사(을/를) 자동 선택 함수(`josa()`, 종성 판별 `(c-0xAC00)%28`)까지 들어 있습니다.

2. **차트 전략을 가장 먼저 정해야 합니다.** 이 레퍼런스의 해답은 "라이브러리 0개, Canvas 2D를 개념마다 처음부터 손코딩(5개)"이고, 재사용 가능한 차트 함수가 **없습니다**. 4-6절의 6단계 레시피(DPR 보정 → 패딩 상수 → `px()`/`py()` 클로저 → L자 축 → 마크 → DOM 범례)를 **공용 함수 하나로 뽑아내는 것만으로도 이 레퍼런스보다 나아집니다.** 또한 축 라벨을 `ctx.font`에 `var(--font-sans)` 값을 넣어 Pretendard로 맞추고, 캔버스 색도 토큰에서 읽으면 테마 전환이 차트까지 따라옵니다.
3. **언급만 되고 안 그려지는 차트를 채우는 것이 가장 큰 개선 여지입니다** — 히스토그램·상자그림·원그래프·꺾은선이 본문에 나오는데 실제 그래픽이 없습니다(2-2차시는 이모지로 대체). 데이터 과학에서 분포를 눈으로 못 보는 건 아쉬운 지점입니다.
4. **파이썬 실행기는 CSS만 있고 구동 코드가 없습니다** — `.pyrun` 스타일을 재사용하려면 Pyodide 로딩·실행·출력 로직을 **직접 만들어야** 합니다. 이 레퍼런스는 데이터 과학 과목인데도 실행 가능한 코드 셀이 0개이고 `<pre>`조차 없습니다. 학생이 코드를 "읽지도 실행하지도" 않습니다 — 의도된 선택인지 미완성인지는 소스만으로 판단할 수 없지만, 우리 과목에서는 명시적 결정이 필요합니다.
5. **가져올 만한 구조적 결정**
   - 차시 1개 = 자기완결 HTML 1개, 공통 CSS/JS만 참조 (빌드·의존성 없음, `file://` 동작 — 학교 컴퓨터실에서 유효한 선택)
   - 인터랙션은 `클래스 + data-*` 선언적 계약으로 공통 엔진이 처리
   - 히어로에 **성취기준 코드 배지** 명시 → 교육과정 추적성
   - "조작 → 🔦 해석" 3단 세트 (활동이 개념으로 착지)
   - 진단 퀴즈의 **누적 연계**(`「정보」 연계` → `1단원` → `1·2단원` → `1~3단원`) — 나선형 복습 장치
   - 마무리 5종 세트(개념 지도 / 일괄채점 단원평가 / 서논술 자기점검 / localStorage 자가평가 / 진로 연계) + 교차 링크 `💡 다시 보면 좋은 곳`
   - **`ds-u4-canvas` 패턴**: 프로젝트 차시에서 학생이 쓴 내용을 마무리에서 다시 불러와 성취감을 주는 흐름 — 이 교과서에서 가장 좋은 아이디어
6. **위젯을 만들 때 지킬 규칙** (이 레퍼런스가 실수한 지점에서 뽑은 것)
   - **resize 핸들러는 `draw`만 부르고 데이터를 다시 만들지 않기** — 5개 캔버스 중 1개가 이걸 어겨서 창 크기를 바꾸면 통계값이 변합니다
   - **위젯이 그 차시의 규칙을 스스로 지키게 하기** — 정규화를 가르치는 차시의 거리 계산이 원단위면 학습 내용과 코드가 모순됩니다
   - **판정 임계값을 화면에 드러내기** — lift 완충 구간(0.9~1.1)처럼 코드에만 있는 기준은 학생이 결과를 해석할 수 없게 만듭니다
   - **본문에 든 예시는 도구로 재현 가능하게** — "빵 → 봉투" 사례처럼 품목 목록에 없는 예를 들면 학생이 확인할 수 없습니다
   - **초기 `render()`가 안내 문구를 덮지 않게** — 4단원 안내 문구 4개가 이 이유로 화면에 안 나옵니다
   - 파괴적 버튼(전체 삭제)에는 확인 절차를 두기
   - 같은 통계는 한 곳에 구현해 공유하기(중앙값·오차 지표가 차시마다 다르게 구현돼 있습니다)
   - 페이지 전용 CSS는 **그 페이지에서만** 쓰기 — `.dd-scn`처럼 다른 차시가 참조하면 조용히 스타일이 깨집니다
7. **피할 것**
   - 공유 블록(마인드맵 핸들러 등)을 4개 파일에 복붙 → 파셜 없는 정적 구조에서는 최소한 공통 JS로 올리기
   - 서술형 `textarea`는 저장하고 자가평가만 저장하는 비대칭 → 서술형도 저장하거나 둘 다 안 하거나로 통일
   - 인쇄 시 위젯을 전부 숨기면서 정적 대체본을 안 주는 것 → 차트는 인쇄용 스냅샷이나 요약 표를 함께 두기
   - `aria-live` 없는 동적 결과, 키보드 접근 불가 툴팁(SVG 개념 지도 노드 포함)
   - 어려운 차시에 용어 툴팁을 빼는 것 — 이 교과서는 가장 어려운 3-2·3-5차시에 툴팁이 0개입니다
   - 4단원처럼 종합 단원에서 계산 위젯을 전부 걷어내는 것 → 프로젝트 단원에서도 학생 데이터로 계산해 보는 창구는 남기기
8. **한계로 인식할 것**: 진도 저장·학습 이력·교사 대시보드·제출 경로가 전혀 없습니다. 수업에서 실제로 평가에 쓰려면 이 부분을 별도로 설계할지 결정이 필요합니다.

### A-1. 이미지 실측 (23개 전수 다운로드)

| 항목 | 값 |
|---|---|
| 총량 | **4.57 MB** (평균 203 KB, 중앙값 119 KB) |

**코드 전체(HTML 628 KB + 공통 자산 61 KB ≈ 0.7 MB)보다 이미지가 6.6배 무겁습니다.** 그리고 최적화가 빠져 있습니다(전부 확인): `width`/`height` 속성 0개 → 레이아웃 시프트, `loading="lazy"` 0개, `srcset` 0개, WebP/AVIF 0개.

가장 낭비가 큰 사례: `server-database.jpg`는 **1280×1926 세로 이미지**인데 `figure.img-figure img`가 `aspect-ratio: 16/9.5` + `object-fit: cover`를 강제하므로, 1000px 컬럼에서 **세로 픽셀의 약 60%가 잘려 보이지 않습니다.** 792 KB를 받아 40%만 씁니다. 우리 프로젝트에서는 **원본을 표시 비율(16:9.5)에 맞춰 미리 크롭**하는 것만으로 큰 폭의 절감이 가능합니다.
- 서버 판정은 **응답 헤더와 404 본문 형태에 근거한 추론**입니다. `/api/chat`에는 요청을 보내지 않았습니다(HEAD로만 확인 → `404`, 즉 이 오리진에서 해당 경로가 라우터에 매칭되지 않음. 별도 프로세스/호스트이거나 다른 실제 경로일 수 있습니다).
- LLM 저작 여부는 **판별 불가**입니다. 균일한 ES5 방언·불변 구조·페이지별 고유 위젯은 LLM 보조 저작과 체크리스트를 든 단독 저자 양쪽에 똑같이 부합하며, 소스에 어떤 귀속 표시도 없습니다.
- `u03-closing.html`은 `</html>` 없이 `</body>`에서 끝납니다(브라우저는 정상 복구).
