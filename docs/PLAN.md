## 5. 데이터 모델

콘텐츠를 HTML에 박지 않고 **데이터로 분리**합니다. 레퍼런스의 최대 약점(같은 위젯·표·탭을 페이지마다 다시 만들고, 공유 블록을 4번 복붙)을 구조적으로 막기 위해서입니다.

### 5-1. `curriculum.json` — 교육과정 (불변 사실)

```jsonc
{
  "subject": { "name": "데이터 과학", "credits": 4, "totalPeriods": 64,
               "source": "2022 개정 교육과정 / 총 차시는 천재 연간 지도 계획 기준" },
  "areas": [
    { "id": 1, "no": "Ⅰ", "name": "데이터 과학의 이해",
      "considerations": ["…성취기준 적용 시 고려사항 원문…"] }
  ],
  "standards": [
    { "code": "12데과01-02", "areaId": 1, "seq": 2,
      "text": "정형 데이터와 비정형 데이터를 구분하고, …",
      "commentary": "데이터의 형태를 바탕으로 …",     // 없으면 null
      "keywords": ["정형 데이터", "비정형 데이터", "속성", "잠재적 가치"] }
  ]
}
```

### 5-2. `lessons.json` — 우리 차시 (설계물)

```jsonc
{
  "id": "01-02",
  "areaId": 1,
  "order": 2,
  "title": "정형과 비정형, 그리고 속성의 가치",
  "lead": "…2~3문장…",
  "standards": ["12데과01-02"],          // 1개 이상 (배열이 계약)
  "periods": "3~4차시",                  // 권장 실제 차시
  "objectives": ["…", "…", "…"],
  "keywords": ["정형 데이터", "속성"],
  "blocks": [ /* §5-4 */ ],
  "status": "draft" | "review" | "done"
}
```

### 5-3. `publishers.json` — 대조표 (출판사별 사실)

```jsonc
{
  "id": "ybm", "name": "YBM", "author": "서인순",
  "tool": "python-jupyter",
  "units": [
    { "no": "Ⅰ", "name": "데이터 과학의 이해",
      "chapters": [
        { "no": "01", "name": "[확인필요]",
          "sections": [
            { "no": "01-1", "name": "데이터 과학의 정의",
              "page": null,                       // 확인 후 채움
              "standards": ["12데과01-01"],        // ← 조인 키
              "verified": false }                  // 사람이 확인해야 true
          ] } ] } ]
}
```

**핵심 설계: 우리 차시와 출판사 단원을 직접 연결하지 않고 성취기준 코드로 조인합니다.**

```
our lesson ──standards[]──▶ 12데과01-02 ◀──standards[]── publisher section
```

이유: ① 콘텐츠 원칙(성취기준이 기준)과 구조가 일치, ② 출판사를 추가해도 우리 차시 데이터를 안 건드림, ③ 대조표가 자동 파생.

`verified: false`인 매핑은 UI에서 **`[확인필요]` 배지**로 노출하고, 절대 확정 사실처럼 보이지 않게 합니다.

### 5-4. 블록 스키마 — 본문의 최소 단위

차시 본문은 블록 배열입니다. 렌더러 하나가 모든 차시를 그립니다.

| `type` | 용도 | 주요 필드 |
|---|---|---|
| `prose` | 설명 문단 | `md` (제한된 마크다운) |
| `objectives` | 학습 목표 | `items[]` |
| `callout` | 개념 확정 / 주의 / 팁 / 활동 | `variant`(`concept`\|`warn`\|`tip`\|`activity`), `label`, `md` |
| `term` | 용어 정의 (본문 내 툴팁 + 용어집 자동 생성) | `term`, `desc` |
| `figure` | 이미지 | `src`, `alt`, `caption`, `credit`, `license`, `w`, `h` |
| `table` | 표 | `head[]`, `rows[][]`, `caption` |
| `chart` | 차트 | `kind`(`scatter`\|`line`\|`bar`\|`hist`\|`box`), `data`, `x`, `y`, `annotations` |
| `code` | 파이썬 실행 블록 | `lang`, `source`, `datasets[]`, `expect`, `editable` |
| `widget` | 개념 조작 위젯 | `name`, `config` |
| `quiz` | 확인 문제 | `items[]` (아래) |
| `crossref` | 이 차시의 3사 위치 | (자동 — 성취기준으로 파생) |

`quiz.items[]` 계약:

```jsonc
{ "q": "…문항…", "type": "mc" | "ox" | "short",
  "choices": ["…"], "answer": 1,          // mc는 인덱스, ox는 true/false
  "explain": "…해설…" }
```

> **레퍼런스에서 배운 방어 규칙 2개를 스키마에 못 박습니다.**
> ① `answer`는 **필수 필드**입니다. 레퍼런스는 `data-correct`를 빠뜨린 문항이 하나 있어 학생이 정답을 맞힐 수 없었습니다. 빌드 시 검증합니다.
> ② `figure`의 `w`/`h`도 필수입니다. 레퍼런스는 23개 이미지 전부에 크기 속성이 없어 레이아웃 시프트가 발생했습니다.

### 5-5. 파생 인덱스 (빌드 시 생성)

- `search-index.json` — 차시·성취기준·용어·출판사 단원명 통합 색인

### 6-3. `Chart` — 레퍼런스가 실패한 지점을 고치는 곳

레퍼런스는 차트 5개를 **각각 처음부터** 손코딩해서 공용 함수가 없었고, 축 폰트가 시스템 폰트와 어긋났고, 색이 토큰을 안 따랐고, 1개는 리사이즈 때 데이터를 재생성하는 버그가 있었습니다. 우리는 하나로 만듭니다.

`Chart` 공용 계약:
- 입력: `{ kind, data, x, y, xLabel, yLabel, annotations[] }` — **데이터는 프롭으로만** 받고 내부에서 절대 생성하지 않음 (리사이즈 재생성 버그 원천 차단)
- 좌표 변환은 `scaleLinear` 유틸 하나로 통일, 여백/눈금/격자선 규칙 고정
- 색은 **CSS 변수에서 읽음** → 테마 바꾸면 차트도 따라옴
- 폰트도 본문 폰트 사용
- 리사이즈: `ResizeObserver` + rAF 스로틀, **재그리기만**
- `aria-label` + `<figcaption>` 필수, 데이터 표 대체본(`<details>`) 자동 제공
- 인쇄용 정적 스냅샷 경로 제공 (레퍼런스는 인쇄 시 차트가 전부 사라집니다)
- 필요 종류: 산점도(+회귀선·잔차), 꺾은선, 막대, **히스토그램, 상자그림** ← 레퍼런스에 없던 것

### 6-4. `PyRunner` — Pyodide

- **지연 로드**: 페이지 진입 시 로드하지 않고 `▶ 실행` 첫 클릭에 로드. 이전에는 "실행하면 파이썬 환경을 내려받습니다(약 N MB)" 안내.
- **자체 호스팅 기본**: 학교망이 CDN을 막는 경우가 있어 Pyodide 자산을 우리 서버에 둡니다. (→ §8 결정 3)
- 패키지 범위가 용량을 좌우합니다: 순수 파이썬만 ≈ 10 MB / `+numpy·pandas` ≈ 25 MB+ / `+matplotlib` ≈ 40 MB+.
- 상태 UI: `미로드 → 로딩(%) → 준비 → 실행 중 → 완료/오류`. 중지 버튼.
- 데이터셋은 `datasets[]`로 선언 → 가상 파일시스템에 미리 적재 (`pd.read_csv('iris.csv')`가 그냥 동작)
- `matplotlib`을 쓰지 않는 방향 권장: 시각화는 파이썬으로 값만 계산하고 그리기는 `Chart`에 넘김 → 용량·일관성 모두 이득
- **폴백 필수**: Pyodide 실패 시 코드와 **예상 출력(`expect`)** 을 정적으로 보여 줍니다(전산실에서 못 돌 수 있음)

## 8. 기술 스택 후보 2개

두 안 모두 **최종 산출물은 정적 파일**입니다(서버 렌더링·DB 없음). 차이는 "빌드를 쓰는가"입니다.

### A안 — 빌드 없는 정적 HTML + 바닐라 JS (레퍼런스 방식의 개량형)

구성: 페이지별 HTML + 공용 `textbook.css` + 공용 `app.js`(ES 모듈) + 콘텐츠 JSON. 빌드·패키지 매니저 없음.

### B안 — Astro (정적 사이트 생성) + 콘텐츠 컬렉션 + 최소 아일랜드

구성: `.astro` 템플릿 + Content Collections(스키마 검증) + 상호작용 컴포넌트만 섬(island)으로 하이드레이션. `npm run build` → 순수 정적 HTML.

### 트레이드오프

| 기준 | **A안 (빌드 없음)** | **B안 (Astro)** |
|---|---|---|
| 학교 전산실 크롬 | ◎ 문제 없음 | ◎ 문제 없음(빌드 결과가 정적) |
| `file://` 더블클릭 실행 | △ **콘텐츠를 JSON으로 분리하면 `fetch`가 CORS로 막혀 동작 안 함.** JSON을 `.js`로 감싸야 함 | ✕ 라우팅·에셋 경로 때문에 사실상 불가 (오프라인은 로컬 서버 배포본으로) |
| 초기 착수 속도 | ◎ 바로 시작 | ○ 초기 세팅 반나절 |
| 27페이지 관리 | ✕ **공통 블록이 페이지마다 복제됨** (레퍼런스가 마인드맵 핸들러를 4번 복붙한 문제 그대로) | ◎ 레이아웃·컴포넌트 1곳 수정 → 전체 반영 |
| 콘텐츠 스키마 검증 | △ 직접 스크립트 작성 | ◎ Content Collections + Zod로 **빌드가 실패**시킴 (§5-4 방어 규칙이 공짜) |
| 검색 색인 | △ 런타임 생성 or 수동 갱신 | ◎ 빌드 시 생성 |
| 3단 레이아웃 + 트리 + 스크롤 스파이 | △ 손으로 상태 관리 (양 늘면 취약) | ◎ 컴포넌트로 격리 |
| 출판사 라벨 전환 | ○ 데이터 주도로 가능 | ◎ 동일 |
| Pyodide 통합 | ◎ 스크립트 직접 로드 | ◎ 아일랜드 하나로 격리, 코드 분할이 쉬움 |
| JS 전송량 | ◎ 최소 | ◎ 아일랜드만 (거의 동등) |
| 다른 교사가 수정 | ◎ HTML만 알면 가능 | △ Node·빌드 이해 필요 |
| 장기 유지보수 | △ 파일 수 늘면 급격히 어려워짐 | ◎ 안정적 |
| 배포 | ◎ 파일 복사 | ○ 빌드 후 복사 (CI 가능) |
| 위험 | 복붙 누적 → 레퍼런스와 동일한 결함 재현 | Node 버전·의존성 관리 부담, 프레임워크 학습 |

### 권고

**B안(Astro)을 권합니다.** 이유는 요구 기능이 레퍼런스보다 무겁기 때문입니다 — 3단 레이아웃 + 성취기준 검색·필터 + 출판사 라벨 전환 + Pyodide는 **공유 상태와 공유 레이아웃이 필수**인데, A안에서는 이걸 27개 파일에 복제해야 합니다. 레퍼런스 분석에서 확인된 결함(공유 블록 4중 복붙, 차시 간 CSS 누출, 표 5번 재구현)은 대부분 "빌드가 없어서 공통화할 수단이 없었다"에서 나왔습니다.

단, **A안의 강점 하나는 반드시 살립니다**: 레퍼런스의 `file://` 동작 목표는 학교 환경에서 실질적 가치가 있습니다. B안을 택하되 **오프라인 배포본(정적 파일 + 간단한 로컬 서버 실행 스크립트)** 을 Phase 5 산출물에 포함합니다.

세 번째 후보였던 **React/Vite SPA는 제외**했습니다. 교과서는 문서 중심이라 클라이언트 라우팅·전역 상태의 이득이 적고, JS 전송량과 초기 렌더 비용만 커집니다.

## 12. 출판사 중립 원칙 (2026-08-05 결정)

우리 학교 채택 교과서는 **YBM**이다. 그러나 사이트는 **어떤 출판사도 기본값으로 두지 않는다.**

### 왜 중립으로 두는가

1. **이 교과서의 기준은 성취기준이다.** 특정 교과서를 기본값으로 두면 화면이 그 교과서 목차 중심으로 읽히고, 성취기준이 뼈대라는 설계가 흐려진다.
2. **채택 교과서는 바뀐다.** 기본값을 코드·데이터에 박으면 채택이 바뀔 때마다 손봐야 한다.
3. **다른 학교도 쓸 수 있다.** 3사를 동등하게 병기하면 어느 학교든 그대로 쓸 수 있다.

### 구현

| 항목 | 처리 |
|---|---|
| 헤더의 교과서 선택 메뉴 | **제거.** 자리에 `교과서 대조표` 링크를 둠 |
| 좌측 트리의 출판사 라벨 전환 | **제거.** 라벨은 항상 교육과정 기준(영역명·차시 제목·성취기준 코드) |
| 선택 상태 저장(`ds-publisher`) | **제거.** localStorage 키가 남지 않음 |
| 차시 하단 `내 교과서에서 찾기` | **유지.** 3사를 항상 나란히 표시 |
| `/crosswalk/` 대조표 | **유지.** 3사 동등 병기 + "고르는 기능을 두지 않은 이유" 안내 |
| `content/publishers.json` | **유지.** 3사 데이터를 동등하게 보관(우열·권장 표시 없음) |

제거한 코드: `PublisherSelect` UI, `app.js`의 `initPublisher`/`applyPublisher`(49줄), `content.js`의 `chapterLabelMap`, `.pub-label` CSS, `data-pub-block` 강조.

### 표시 순서에 대하여

`publishers.json`의 순서(YBM → 씨마스 → 천재)는 **우열이나 권장을 뜻하지 않는다.** 대조표 화면에 그 취지를 명시해 두었다.
